# 思维链 Cot

2022年的论文表示（现如今已经训练到了模型里面，也就是推理模型。）

通过提示词指示模型“逐步思考”，将复杂任务分解，并在对话中输出思维拆解过程，作为了提示词的一部分。

作用：因为模型的输出会影响最终的结果，让模型不断拆解并输出，可以减少模型幻觉，提高准确率。



# 思维树 ToT

2023年的论文（不能确定模型是否有这个能力。可以考虑作为agent开发的技巧。）

思维链是从上往下直线解题，思维树是一个树状结构，在解题的每一步都进行拆解思考，由此可以找到解题最佳路线，也可以通过广度/深度优先的路线解题。

# 推理 + 执行（ReAct）重要

2023年的论文

区别于思维树，思维树是在做任务拆解的时候就已经输出了，又因为输出会影响后面的输出，所以如果输出的路线是错的，就会增加模型的幻觉。

而 ReAct，是先大量推理通过推理产生的traces帮助模型归纳、更新纠正行动计划，再通过与知识库等外部工具信息进行交互去执行输出结果。循环以上步骤，直到完成任务。


# 自我反思（Reflexion）重要

2023年的论文

在 ReAct 的基础上，增加了反思能力，失败经验中学习。

具体：把梯度更新中的参数信号转变为添加到模型上下文的语言总结，，用到了记忆存储，做到从失败经验中学习的能力。


# 无需观察的推理 ReWOO

2023年的论文

相对于 ReAct 的每执行一步观察一步，ReWOO 省去了观察的步骤，显著提升效率。

因为省去观察了，所以可能存在推理的错误。

所以针对这种智能体增加了设计模式分为三个模块：

- 规划器（Planner）
一次推理完所有，包含错的对的。

- 执行器（Worker）
一次执行完所有，包含错的对的。

- 求解器（Solver）
这是重点，得到执行器结果后，不直接输出，通过求解器对所有结果总结梳理，再输出。


优缺点

ReWOO 确实可以显著提升效率，但是因为只推理一次，对于提高信息有限不够详情的场景，准确度是不如 ReAct。

- ReAct ReWOO 两者对比

- ReAct：每步都会调用模型
（执行一步 + 调用模型观察结果）* N 次执行

- ReWOO：只调用模型2次（第一次分解所有 + 最后一次求解总结）
1次调用模型分解所有 + N 次执行 + 1次总结
