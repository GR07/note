# 跨线程共享

AI 通过读取你专属的“长期档案（User ID）”，这就是跨线程读取存档。

**重点：** 短期记忆按线程（thread_id）切分，长期记忆按用户（user_id）挂载。Checkpointer 自动托管线程，Store 手动管理用户。

**注意：** 代码里的 `in_memory_store` 是存在内存里的，关掉程序档案就没了。以后实际做项目，把它换成 `Postgres` 或 `Redis` 版本的 Store，你的 AI 就拥有永久记忆了。

```python
# ==============================================================================
# 第一步：导入工具箱
# ==============================================================================
import os
import uuid  # 用于给存入的记忆生成唯一 ID
from typing import Annotated
from typing_extensions import TypedDict

from langchain_deepseek import ChatDeepSeek
from langchain_core.runnables import RunnableConfig # 用于接收配置信息 (user_id)
from langchain_openai import OpenAIEmbeddings        # 用来调用国产嵌入模型

from langgraph.graph import StateGraph, MessagesState, START
from langgraph.checkpoint.memory import MemorySaver  # 短期记忆（记事本）
from langgraph.store.memory import InMemoryStore     # 长期记忆（超级档案柜）
from langgraph.store.base import BaseStore           # 用于类型提示


# ==============================================================================
# 第二步：初始化核心组件（大脑与记忆库）
# ==============================================================================

# 1. 初始化大模型（思考大脑）
model = ChatDeepSeek(
    model="Pro/deepseek-ai/DeepSeek-V3",
    temperature=0,
    api_key=os.environ.get("DEEPSEEK_API_KEY"),
    base_url=os.environ.get("DEEPSEEK_API_BASE"),
)

# 2. 初始化长期记忆库（Store）
# 比喻：建立一个超级档案柜，并配了一台“指纹识别机”（Embedding），方便按语义搜索
in_memory_store = InMemoryStore(
    index={
        "embed": OpenAIEmbeddings(
            model="Pro/BAAI/bge-m3", # 国产好用的向量化模型（把文字变成数学数组）
            api_key=os.environ.get("DEEPSEEK_API_KEY"),
            base_url=os.environ.get("DEEPSEEK_API_BASE") + "/v1",
        ),
        "dims": 1024, # 维度大小
    }
)


# ==============================================================================
# 第三步：编写核心逻辑（AI 的上班手册）
# ==============================================================================
# 注意这里多了 config 和 store 两个参数
def call_model(state: MessagesState, config: RunnableConfig, *, store: BaseStore):
    
    # 1. 获取用户的“身份证号”（User ID）
    # 我们从传入的配置中拿到 user_id。这决定了去哪个专属抽屉找记忆。
    user_id = config["configurable"]["user_id"]
    namespace = ("memories", user_id) # 设定档案的存储路径（类似 文件夹/memories/user_1）
    
    # 2. 检索记忆（查档）
    # 用用户刚刚说的话（state["messages"][-1].content）去档案柜里搜索相关的历史记忆
    memories = store.search(namespace, query=str(state["messages"][-1].content))
    
    # 把搜出来的记忆拼成一段长文本（info）
    info = "\n".join([d.value["data"] for d in memories])
    
    # 3. 洗脑（注入 System Prompt）
    # 把查到的人设信息塞给 AI，让它带着“偏见”去回答问题
    system_msg = f"你是一个正在与用户交谈的小助手。用户信息：{info}"
    
    # 4. 记笔记（存入长期记忆）
    last_message = state["messages"][-1]
    # 如果用户说了“记住”或者“remember”...
    if "记住" in last_message.content.lower() or "remember" in last_message.content.lower():
        # 【演示用硬编码】实际开发中，这里应该让大模型去提取关键信息，这里为了演示直接写死
        memory = "用户名字是tomiezhang" 
        # 把记忆存进专属抽屉。用 uuid 生成一个随机编号作为文件名。
        store.put(namespace, str(uuid.uuid4()), {"data": memory})
    
    # 5. 呼叫大模型
    # 将带有记忆的 System 消息 和 用户的历史聊天记录一起发给大模型
    response = model.invoke(
        [{"role": "system", "content": system_msg}] + state["messages"]
    )
    
    # 返回回答，更新流水线状态
    return {"messages": response}


# ==============================================================================
# 第四步：搭建并组装流水线
# ==============================================================================
builder = StateGraph(MessagesState)
builder.add_node("call_model", call_model)
builder.add_edge(START, "call_model")

# 见证奇迹的时刻：同时挂载短期记忆和长期记忆！
# checkpointer=MemorySaver()   -> 记住当前聊天窗口（短期）
# store=in_memory_store        -> 记住这个人（长期，跨窗口）
graph = builder.compile(checkpointer=MemorySaver(), store=in_memory_store)


# ==============================================================================
# 第五步：验收测试（跨聊天室试探）
# ==============================================================================

# 【测试 1】：在聊天室 "1" 里，让 AI 记住名字
# 注意：thread_id 是 "1"，代表新建的聊天窗口。user_id 是 "1"，代表用户本人。
config = {"configurable": {"thread_id": "1", "user_id": "1"}}
input_message = {"role": "user", "content": "请记住我的名字叫tomiezhang!"}

print("--- 第一次对话（聊天室 1） ---")
for chunk in graph.stream({"messages": [input_message]}, config, stream_mode="values"):
    chunk["messages"][-1].pretty_print()

# (此时，AI 因为触发了“记住”，已经把 tomiezhang 写进了 user_1 的超级档案柜)


# 【测试 2】：换一个全新的聊天室 "2"，考它！
# 注意：thread_id 变成了 "2"！这意味着你关掉了刚才的窗口。
# 但是，user_id 依然是 "1"。这就是跨线程记忆的体现！
config = {"configurable": {"thread_id": "2", "user_id": "1"}}
input_message = {"role": "user", "content": "我叫什么名字?"}

print("\n--- 第二次对话（聊天室 2，全新窗口） ---")
for chunk in graph.stream({"messages": [input_message]}, config, stream_mode="values"):
    chunk["messages"][-1].pretty_print()

# 运行结果：虽然换了聊天室，但 AI 会回答：“你叫 tomiezhang！”
```


# 语法解惑

## 为什么这三个参数不能在 graph = builder.compile(checkpointer=MemorySaver(), store=in_memory_store) 全部传入

compile 是“建厂”，只传基础设施（store, checkpointer）。

stream 是“接客”，才传动态的凭证（config）和业务数据（state）。


## checkpointer=MemorySaver() 这个参数用在哪了？

因为在 `call_model` 的函数签名里，你**根本没有看到** `checkpointer` 这个参数（没有像 `store` 那样写在函数里），对吧？

**答案是：`checkpointer` 不是给你的节点函数（`call_model`）直接用的，它是给 LangGraph 这个“大管家（框架）”在后台偷偷用的。**

---

### 1. 它被安装在哪里？
```python
graph = builder.compile(checkpointer=MemorySaver())
```
在“建厂（compile）”的时候，你把这个存档机安装在了**流水线的总控室**里。它属于整个工厂的基础设施。

### 2. 它是怎么工作的？（幕后操作）

当你发起对话请求时：
```python
config = {"configurable": {"thread_id": "1"}}
graph.stream({"messages": [input_message]}, config, ...)
```
LangGraph 框架在后台会执行以下三步“暗箱操作”，全程都不需要你干预：

*   **动作一（自动读档）**：框架看到你传了 `thread_id: "1"`。它立刻去 `checkpointer`（存档机）里找：“1号聊天室之前有存档吗？”
    *   如果有，框架会自动把之前的聊天记录**全部提取出来**。
    *   然后把你刚发的 `input_message` 追加到最后。
    *   接着，框架把合并好的**完整聊天记录**，作为 `state` 参数，递给了你的 `call_model` 函数。
*   **动作二（你的函数干活）**：你的 `call_model(state)` 接收到了这串长长的历史消息，发给大模型，大模型回答完毕，`return {"messages": response}`。
*   **动作三（自动存档）**：框架拿到了你返回的新消息，它不会直接结束，而是自动把这个更新后的状态（连同之前的记录），**再次塞进 `checkpointer` 里保存起来**。这样下次对话时，就又能读到了。

---

### 💡 为什么它不写在参数里？（对比 Store）

*   **`store`（长期记忆）**：你需要**主动去查**。所以你要在代码里写 `store.search(...)`，这意味着你必须在函数参数里声明它，把它拿在手里用。
*   **`checkpointer`（短期记忆）**：它是**全自动的**。它就像是游戏里的“自动存档点”。你玩过关卡（执行完节点），系统自动帮你存；你下次读档（同一个 thread_id 发起请求），系统自动帮你把数据填好交给你（变成 `state`）。**你不需要主动去操作它，所以它不需要出现在函数参数里。**

---

### 📝 小白笔记一句话总结：

**`checkpointer` 是一台装在总控室的“全自动录像机”。它拦截了每次请求的开始和结束，自动根据 `thread_id` 把历史状态“读”出来塞给 `state`，把新状态“存”进去。你的节点函数只管处理 `state`，完全不需要、也拿不到 `checkpointer`。**

**反证法**：如果你在 `compile()` 时**不写** `checkpointer=MemorySaver()` 会怎样？那这台录像机就没了。每次 `stream` 传进来的 `state`，就仅仅是当次你发的 `{"messages": [input_message]}`，历史记录全丢，AI 又变回金鱼了。

---

### 📝 总结

*   **两个核心参数：**
    *   `thread_id` = **聊天室门牌号**（管短期记忆，换聊天室就清空）。
    *   `user_id` = **用户身份证号**（管长期记忆，跟着人走，换聊天室也能查到档案）。
*   **长期记忆的闭环三步曲：**
    1.  **存 (`store.put`)**：发现关键信息，写进档案柜。
    2.  **查 (`store.search`)**：基于用户的*最新问题*，去档案柜里找最像的记忆（语义搜索）。
    3.  **用（System Prompt）**：把查到的记忆包装成“上帝指令”，强行灌输给大模型。
