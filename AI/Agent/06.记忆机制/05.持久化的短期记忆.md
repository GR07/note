# MongoDB 数据库连接

这里 demo 只是持久化的短期记忆

**重点：** 短期记忆按线程（thread_id）切分，长期记忆按用户（user_id）挂载。Checkpointer 自动托管线程，Store 手动管理用户。


# 真正的长期记忆（store）是什么？

是跟着 user_id（用户本人）走的。不管你换多少个 thread_id，只要你是同一个 user_id

所以，MongoDBSaver 只是给某一个具体的聊天室（Thread）做了一份永久的“聊天记录备份”。它叫持久化的短期记忆。

```python
# ==============================================================================
# 第一部分：导入所需的工具箱
# ==============================================================================
import os
from typing import Literal
import pymongo  # 用于连接和测试 MongoDB 数据库
from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek

# LangGraph 的“一键生成 Agent”神器 和 MongoDB 存档器
from langgraph.prebuilt import create_react_agent
from langgraph.checkpoint.mongodb import MongoDBSaver


# ==============================================================================
# 第二部分：测试数据库连通性（可选，但实战建议有）
# ==============================================================================
# 1. 创建 MongoDB 客户端连接 (默认端口 27017)
client = pymongo.MongoClient("mongodb://localhost:27017/")

# 2. 测试连接是否成功
try:
    # 发送一个 ping 命令测试
    client.admin.command('ping')
    print("✅ MongoDB连接成功！")
except Exception as e:
    # 如果报错，打印失败原因
    print(f"❌ MongoDB连接失败: {e}")


# ==============================================================================
# 第三部分：定义工具与初始化大脑
# ==============================================================================

# 1. 定义工具（AI 的“手脚”）
@tool
def get_weather(city: Literal["北京", "深圳"]):
    """用来返回天气信息的工具函数。"""
    # 【重点】使用 Literal 限制了大模型只能输入“北京”或“深圳”，防止它乱填其他城市导致报错
    if city == "北京":
        return "北京天气晴朗 大约22度 湿度30%"
    elif city == "深圳":
        return "深圳天气多云 大约28度 湿度80%"
    else:
        raise AssertionError("Unknown city")

# 把工具装进列表
tools = [get_weather]

# 2. 初始化大模型大脑（这里使用的是 DeepSeek-V3）
model = ChatDeepSeek(
    model="Pro/deepseek-ai/DeepSeek-V3",
    temperature=0, # 温度为 0，保证严谨
    api_key=os.environ.get("DEEPSEEK_API_KEY"),
    base_url=os.environ.get("DEEPSEEK_API_BASE"),
)


# ==============================================================================
# 第四部分：连接持久化数据库 & 一键生成 Agent
# ==============================================================================

# 1. 设定数据库连接字符串
MONGODB_URI = "localhost:27017" # 如果是云数据库，请替换为云端的连接 URI

# 2. 使用上下文管理器（with）安全地连接数据库
# 这样做的好处是：程序运行结束后，会自动安全地断开数据库连接
with MongoDBSaver.from_conn_string(MONGODB_URI) as checkpointer:
    
    # 3. 【核心黑科技】使用 create_react_agent 一键生成带记忆和工具的工作流！
    # 以前的复杂画图（add_node, add_edge）统统不需要了，传给这个函数就行：
    # model: 大脑
    # tools: 手脚
    # checkpointer: 数据库记忆
    graph = create_react_agent(model, tools=tools, checkpointer=checkpointer)
    
    # 4. 设置会话凭证（thread_id 决定了记忆存在哪个档案袋里）
    config = {"configurable": {"thread_id": "1"}}
    
    # 5. 发起提问
    print("\n--- 用户提问 ---")
    response = graph.invoke(
        # 使用元组格式 ("human", "内容") 传递消息
        {"messages": [("human", "北京今天的天气如何？")]}, 
        config # 必须带上 config，把通行证交进去
    )
    
    # 6. 打印 AI 的最终回答（取返回消息列表的最后一条）
    print("\n--- AI 回答 ---")
    print(response["messages"][-1].content)
```

---

### 📝 总结

1.  **告别内存，拥抱数据库**：
    *   之前的 `MemorySaver` 是存在内存里的，一关机就没了。
    *   现在的 `MongoDBSaver` 存在硬盘里，**真正实现了断点续传和永久记忆**。实际项目中，你还可以换成 `PostgresSaver` 等。
2.  **`Literal` 的妙用**：
    *   在定义工具参数时，用 `Literal["北京", "深圳"]` 代替单纯的 `str`。大模型看到这个约束，就知道“哦，我只能填这两个词”，极大减少了幻觉导致的调用错误。
3.  **一键封装神器 `create_react_agent`**：
    *   如果你只需要一个“大模型 + 工具循环”的标准 Agent，完全不需要手动去写 `StateGraph`、画条件边。
    *   直接调用这个官方函数，传入 `model`、`tools` 和 `checkpointer`，它会自动帮你把底层的逻辑图搭好并编译。
4.  **`with` 上下文管理器**：
    *   连接数据库时，务必使用 `with ... as ...:` 的写法，它可以帮你自动管理连接的开闭，防止连接泄漏导致数据库卡死。
