# 初始配置

使用 OpenAI 官方的 Python SDK，通过修改 OPENAI_BASE_URL 把请求转发到了 DeepSeek 的 API，这是兼容 OpenAI 接口的常见用法。

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-f7xxxxxx",# 接口密钥
    base_url="https://api.deepseek.com"# 接口地址
)

client = OpenAI()

completion = client.chat.completions.create(
    model="deepseek-flash", # 选择模型
    messages=[ # 发送对话
        {
            "role": "user",
            "content": "你是谁？，介绍下能力" # 用户的问题
        }
    ],
    # 温度参数
    temperature=0.8,
    # 开始流式输出
    stream=True,
)
# 全部准备完成再输出结果
print(completion.choices[0].message.content)
# 迭代器 逐个打印最新增量内容
for chunk in completion:
    print(chunk.choices[0].delta.content, end="|")
```



## message 对象

与 LLM 的对话是通过 **消息 (Message)** 进行的，每个消息都是一个字典，包含以下关键信息：

- **`role` (角色)**：消息的发送者角色。
  - `"user"` **(用户)**：代表用户的消息。
  - `"assistant"` **(AI助手)**：代表 LLM 给出的回复。
  - `"system"` **(系统)**：代表对给 LLM 的设定，如你是一个专业的前端开发，思考问题的角度需要参考xxxx规则，一般放在最顶部。
- **`content` (内容)**：消息的具体文本内容，即对话内容。




## temperature 温度参数

温度可以控制 LLM 生成文本的 **创造性和随机性**，范围0-2，默认为1：

**越接近 0**：生成的文本更 **保守、重复性高**，更倾向于选择最有可能的Token。适合需要准确性和一致性的任务，例如事实、代码、数学相关等。

**越接近2**：生成的文本更 **创新、发散、重复性低**，更倾向于选择不太常见但仍然合理的Token。适合需要创造性和灵感的任务，例如故事创作、头脑风暴等。



## stream 流式输出

默认情况下，API 会等模型把整段话全部生成完，才一次性返回结果。开启 `stream=True` 后，模型每生成一小段内容就会立刻返回一个 `chunk`（数据块），你可以边接收边打印，实现类似 ChatGPT 网页版那样"逐字输出"的效果。


```python
from openai import OpenAI
client = OpenAI()

completion = client.chat.completions.create(
    model="deepseek-flash", # 选择模型
    messages=[ # 发送对话
        {
            "role": "user",
            "content": "你是谁？，介绍下能力" # 用户的问题
        }
    ],
    temperature=2,
    stream=True,
)

for chunk in completion:
    print(chunk.choices[0].delta.content, end="|")
```

**与普通输出的区别：**

| 对比项 | 普通输出 | 流式输出 |
|--------|----------|----------|
| 参数 | `stream=False`（默认） | `stream=True` |
| 返回 | 一次性返回完整 `completion` | 返回一个可迭代的生成器 |
| 取值 | `completion.choices[0].message.content` | `chunk.choices[0].delta.content` |
| 适用 | 只需要最终结果 | 需要实时显示、打字机效果 |


**注意几个要点：**

1. 流式输出时用的是 **`delta`**，不是 `message`，即 `chunk.choices[0].delta.content`。
2. 流式返回中，`delta.content` 有时会是 `None`（比如开头或结尾的空块），直接拼接时最好加个判断：

```python
for chunk in completion:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
```

3. 例子里的 `end="|"` 只是为了在演示时看清每块内容的分隔，实际使用时通常改成 `end=""`，这样输出连贯。
4. 加上 `flush=True` 可以保证内容实时刷新到屏幕，不会因缓冲区延迟显示。
