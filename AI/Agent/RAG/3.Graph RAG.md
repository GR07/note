# Graph RAG

**针对“信息分散”**：**Graph RAG** 通过知识图谱把实体连起来，能够跨文档、跨块地提取出完整的实体关系链，拼凑出完整上下文。


传统 RAG，核心是“基于文本片段的向量相似度检索”。**Graph RAG（基于图的检索增强生成）则是它的进阶形态，它用“知识图谱”替代或补充了传统的“文本片段库”，让检索从“找相似的句子”升级为“沿着实体间的关联网络找答案”**。


### 🕸️ 核心区别：从“翻书”到“顺网找线索”

传统 RAG 和 Graph RAG 的根本差异在于**信息的组织与检索方式**。

| 维度 | 传统 RAG (Vector RAG) | **Graph RAG** |
| :--- | :--- | :--- |
| **知识存储** | 扁平的文本片段（Chunks） | 结构化的**知识图谱**（节点=实体，边=关系） |
| **检索逻辑** | 向量相似度：找语义上最接近的文本段 | **图遍历/查询**：沿关系链（A→B→C）定位关联实体 |
| **核心优势** | 实现简单，对**单跳事实型问题**效率高 | 擅长**多跳推理**和**复杂关系查询**，上下文更完整 |
| **典型短板** | 难以处理需要**组合多个分散事实**的问题 | 图谱构建有**信息损耗**，对简单问题可能“过度设计” |

### ⚙️ 它是如何工作的？

Graph RAG 的流程可以理解为“**先建图，再查图**”。

**1. 离线构建：把文本变成知识图谱**
系统会先用 NLP 技术从文档中提取“实体”（如人物、公司）和它们之间的“关系”，构建成一张知识图谱（如“爱因斯坦 —提出→ 相对论”）。这张图谱就是后续检索的结构化知识库。

**2. 在线查询：在图上“顺藤摸瓜”**
当用户提问时，Graph RAG 不再只做向量匹配，而是会：
*   **解析查询**：识别问题中的关键实体和关系。
*   **图检索**：在知识图谱中定位相关节点，并**沿着关系边遍历**（如广度/深度优先搜索），把与问题相关的实体、关系和原始文本片段一并找出来。
*   **增强生成**：将这份结构化的“证据链”作为上下文，喂给大模型生成最终答案。


### 🎯 局限：

*   **效率**：当不需要关系时，例如“法国的首都是哪里”，传统 RAG 直接向量检索文本片段就足够高效。

*   **图谱构建风险**：自动抽取的图谱可能不完整。有测试表明，纯三元组图谱的实体覆盖率可能只有约 **65%**，这意味着大量信息在“建图”阶段就丢失了，反而可能导致回答质量下降。

### 💎 总结

Graph RAG 的核心思想是**用结构化的“关系”来增强检索**。它适合处理**需要串联多个实体、进行多步逻辑推理**的复杂问题，但在简单的、事实查找型的问题上，传统 RAG 往往更直接、更经济。两者并非替代关系，而是面向不同问题复杂度的互补方案。
