
# 当多个节点同时更新同一个字段时，该怎么合并？

```python
from typing_extensions import Annotated, TypedDict  # 导入Annotated（给类型附加"合并规则"）和TypedDict（定义State）

def reducer(a: list, b) -> list:        # 定义一个"合并函数"（归约器），告诉框架：
                                        # 旧值a和新值b碰头时，应该怎么合成一个新值
    if b is not None:                   # 如果节点确实返回了新内容（b不是空）
        return a + [b]                  # 就把b追加到旧列表a的后面，返回合并后的新列表
    return a                            # 如果b是空（节点没更新这个字段），就保留旧值a不变

class State(TypedDict):                 # 定义共享黑板State的结构
    x: Annotated[list, reducer]         # 关键写法！字段x是一个列表，
                                        # Annotated[list, reducer]的意思是：
                                        # "x是list类型，并且当多个节点都更新x时，
                                        #  用reducer函数来合并它们的更新"
```

---

## 为什么需要这个东西？

回顾一下之前学的规则：**节点返回的是"部分更新"，框架负责合并进 State**。

之前的例子里，`text` 是字符串，一个节点返回新值就直接覆盖旧值——很简单。

但 LangGraph 支持**并行节点**（几个节点同时跑）。假设节点1返回 `{"x": 1}`，节点2返回 `{"x": 2}`，两者都要更新 `x`，框架就会困惑：

> 到底听谁的？直接覆盖，还是都保留？

默认行为是**直接覆盖**（后写的赢），可能丢数据。而 `Annotated[list, reducer]` 就是给这个字段挂一个"**合并裁判**"：多个更新到达时，别急着覆盖，先交给 `reducer` 函数处理。

## 这段代码的效果演示

```python
# 初始: x = [1, 2]
# 节点1返回 {"x": 3}，节点2返回 {"x": 4}
# 框架调用 reducer([1, 2], 3) → [1, 2, 3]
#            reducer([1, 2, 3], 4) → [1, 2, 3, 4]
# 最终: x = [1, 2, 3, 4]  ← 所有更新都保留下来了！
```

## 类比理解

- 没有 reducer：多人同时往一个格子里写字，**后写的把先写的盖掉了**。
- 有 reducer：配了一个**文书员**，收到所有修改后统一誊抄到本子后面，**一条都不丢**。

## 实际应用

LangGraph 官方最常用的就是这个模式，专门用来累积对话消息：

```python
from operator import add
from typing import Annotated

class State(TypedDict):
    messages: Annotated[list, add]  # add是Python内置函数，效果同a + b
```

真实 Agent 里，每个节点产生的新消息（LLM回复、工具结果）都通过这种方式追加到 `messages` 列表里，形成完整的对话历史。

一句话总结：**`Annotated[类型, 合并函数]` = 给 State 字段指定"多人同时修改时怎么合并"的规则**，是构建并行节点、消息累积的基础。
