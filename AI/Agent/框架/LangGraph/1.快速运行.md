```bash
pip install -U langgraph
```

LangGraph 的核心思路，是把 AI 工作流显式地写成**图（Graph）** ：**节点（Node）** 负责执行逻辑，**边（Edge）** 决定跳转方向，一个共享的 **状态（State）** 在节点之间流动和更新。下面从安装、核心概念、可运行示例到进阶用法，逐步展开。


---

# 核心概念：State、Node、Edge、Graph

LangGraph 围绕四个组件展开：

| 组件 | 作用 |
|---|---|
| **State** | 用 `TypedDict` 或 Pydantic 模型定义，是所有节点读写的“共享内存”。节点返回的是**部分更新**，而不是完整状态。 |
| **Node** | 一个纯函数，接收当前 `State`，返回需要更新的字段字典。可以是 LLM 调用、工具执行、路由判断等。 |
| **Edge** | 连接节点。普通边固定跳转；**条件边**根据 State 中的值动态决定下一个节点。 |
| **Graph** | 由 `StateGraph` 实例化，添加节点和边后，必须调用 `.compile()` 才能执行。 |

一个关键细节：节点函数**必须返回字典**，只包含要更新的键；如果直接修改传入的 `state` 并返回整个 state，LangGraph 可能不会按预期合并状态。

# 最小可运行示例：线性工作流

下面是一个最基础的 LangGraph 程序，两个节点顺序执行，展示 State 如何逐步更新：

```python
# 从 langgraph.graph 模块导入两个特殊常量/类：
#   START —— 表示图的起点（虚拟节点），用于指定从哪个节点开始执行
#   StateGraph —— 构建基于状态的有向图的核心类
from langgraph.graph import START, StateGraph

# 从 typing_extensions 导入 TypedDict：
#   用于定义「带类型的字典」结构，这里用来描述图的状态 schema
from typing_extensions import TypedDict


# 定义图的状态结构 State，继承 TypedDict
# 说明：LangGraph 中每个节点接收一个 state，返回一个「部分更新」的 dict
class State(TypedDict):
    # 状态中只有一个字段 text，类型为 str
    # 节点会不断读写这个字段，把它当作在节点之间流转的共享上下文
    text: str


# 定义节点 A：它是一个普通函数，接收当前状态 state，返回需要更新的字段
def node_a(state: State) -> dict:
    # 读取 state["text"]，在末尾拼接字符 "a"，返回 {"text": 新值}
    # 注意：返回的 dict 是「局部更新」，LangGraph 会自动把它合并回全局状态
    return {"text": state["text"] + "a"}


# 定义节点 B：同样接收状态、返回更新
def node_b(state: State) -> dict:
    # 读取当前 text（此时可能已包含 node_a 追加的 "a"），再追加 "b"
    return {"text": state["text"] + "b"}


# 实例化一个 StateGraph，并把 State 作为整个图的状态类型
# 之后所有节点的输入/输出都会被校验为 State 结构
graph = StateGraph(State)

# 向图中注册节点，节点名 "node_a" 与实现函数 node_a 绑定
graph.add_node("node_a", node_a)

# 再注册节点 "node_b"，与函数 node_b 绑定
graph.add_node("node_b", node_b)

# 添加一条边：START -> node_a
# START 是图的内置起点，表示「图开始执行时先进入 node_a」
graph.add_edge(START, "node_a")

# 添加一条边：node_a -> node_b
# 表示 node_a 执行完毕后自动流转到 node_b（顺序执行）
graph.add_edge("node_a", "node_b")

# 编译图，得到可运行的 app 对象
# 编译阶段会做结构校验（是否有孤立节点、是否可达等），并生成可 invoke 的执行器
app = graph.compile()

# 调用 app.invoke，并传入初始状态 {"text": ""}
# 执行流程：START -> node_a（"" 变成 "a"）-> node_b（"a" 变成 "ab"）
# 因为没有更多边，流程结束，返回最终状态
print(app.invoke({"text": ""}))
# 输出: {'text': 'ab'}
```
流程是：START → node_a（追加 "a"）→ node_b（追加 "b"），最终状态中的 text 变为 "ab"

## 关键点小结

| 概念 | 作用 |
|------|------|
| `State` | 全图共享的状态结构，节点通过读写它来传递数据 |
| `add_node` | 注册节点，名字任意，第二参数是实际执行的函数 |
| `add_edge` | 定义节点间的流转方向，`START` 是虚拟起点 |
| `compile()` | 校验 + 生成可执行图，返回的 `app` 可 `invoke` / `stream` |
| 节点返回值 | 是「部分更新」，会被合并进全局状态，而不是替换整个 state |

> 补充：LangGraph 默认对 `TypedDict` 字段采用 **覆盖式更新**。如果字段是列表并想“追加”语义，应改用 `Annotated[list, operator.add]` 之类的 reducer。本例中 `text` 用覆盖方式，所以每次返回的是拼接后的完整字符串。
