# 条件路由

这段代码在上一段的基础上升级了：**引入了条件边（循环）**

```python
from langgraph.graph import START, END, StateGraph  # 导入：起点START、终点END、画图工具StateGraph
from typing_extensions import TypedDict              # 导入TypedDict，用来定义State的数据结构

class State(TypedDict):          # 定义"共享黑板"的结构
    text: str                    # 黑板上有两个字段：text（字符串）
    count: int                   # 和 count（整数，用来做计数器）

def increment(state: State) -> dict:                 # 节点函数：干活的工位，负责计数
    return {"count": state["count"] + 1}             # 取出count，加1，只返回要更新的这一个字段

def should_continue(state: State) -> str:            # 条件边函数：当"导航员"，决定下一步去哪
    if state["count"] < 3:                           # 看黑板上的count，如果还没加到3
        return "increment"                           # 就返回"increment"，意思是：回去再执行一次increment节点
    return END                                       # 否则返回END，意思是：流程结束（END是特殊终点标记）

graph = StateGraph(State)                    # 创建一张图，告诉它黑板长什么样
graph.add_node("increment", increment)       # 把increment函数注册成节点，名字叫"increment"
graph.add_edge(START, "increment")           # 画箭头：从起点 → increment（流程从这里开始）
graph.add_conditional_edges("increment", should_continue)  # 给increment画一条"条件边"：
                                             # 每次执行完increment，就调用should_continue看黑板，
                                             # 根据它返回的值决定是继续循环，还是走向END

app = graph.compile()                        # 编译图纸，变成可运行的程序
result = app.invoke({"text": "hello", "count": 0})  # 启动流程，初始状态：text="hello"，count=0
print(result)                                # 打印最终状态
# 输出: {'text': 'hello', 'count': 3}
```

---

## 执行过程拆解（为什么 count 最后是 3？）

这个图的结构是 `START → increment →（条件判断：继续 or 结束）`，相当于一个**循环**：

| 轮次 | 执行 increment 前 count | should_continue 看到 | 决定 |
|---|---|---|---|
| 第 1 次 | 0 | `0 < 3` ✅ | 继续循环 |
| 第 2 次 | 1 | `1 < 3` ✅ | 继续循环 |
| 第 3 次 | 2 | `2 < 3` ✅ | 继续循环 |
| 第 4 次 | 3 | `3 < 3` ❌ | 返回 END，结束 |

所以 `count` 被加了 3 次，最终是 3。注意：**循环体最后一次执行完后，还会再判断一次条件**，发现该结束了才停。

## 两个容易混淆的点

1. **`add_conditional_edges` 的用法**：它不需要你提前写死箭头指哪，而是挂上"导航函数"，**运行时**看 State 的值临时决定路线。这就是 Agent 能"思考后再决定下一步"的基础。

2. **为什么 `text` 没变？** 因为没有任何节点返回 `text` 字段。这正好印证了之前学的关键规则——**节点只更新自己返回的键，其他字段原样保留**。所以 `"hello"` 一路穿到最后。

## 和上一段代码对比

| | 上一段 | 这一段 |
|---|---|---|
| 节点数 | 2 个（a → b 直线） | 1 个（自己循环） |
| 边的类型 | 普通边 | 普通边 + **条件边** |
| 结束方式 | 没写 END，跑完就停 | 显式返回 `END` |
| 能力 | 顺序执行 | **循环 / 路由** ← Agent 的核心能力 |

可以把 `increment` 想象成 Agent 的"思考一步"，`should_continue` 想象成"判断还要不要继续思考"——真实 Agent 就是用这个循环结构在"调用工具"和"给出答案"之间反复运转的。
