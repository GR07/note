# command 与 skill

本质上，命令和 skill 加载到 AI 上下文中的指令内容几乎一致

命令是用户手动触发的快捷入口，skill 是更灵活的内部能力包——可以由 AI 主动调用、被其他工作流调用、或在系统判断相关时自动加载。

command 是 skill 的命令式封装

use_skill("openspec-propose")


# explore

1. 用 openspec list --json 检查当前有哪些 change，如果相关就读取，结合联想。

2. AI 进入“只思考、不编码”的探索模式


只思考、不编码，帮助用户理清问题、比较方案、澄清需求。





# propose

1. 描述中提取 kebab-case 名称

2. 创建变更目录 openspec new change "<name>"

3. 获取 artifact 构建顺序

4. 按依赖顺序逐个创建 artifact（涉及读取模板按约束编写）

5. 完成后，提示：所有 artifact 已就绪，引导用户运行 /opsx:apply

确认意图 → 创建 change → 查询状态 → 按依赖生成 artifacts → 确认完成 → 提示 /opsx:apply。



# apply

1. 选择 change

2. 理解 schema （模板-工作流类型）

3. 通过指令拿到当前任务列表及各自状态（已完成/待完成）

4. 循环实现任务


选择 change → 检查状态 → 获取 apply 指令 → 读上下文文件 → 展示进度 → 循环实现任务 → 标记完成 → 完成或暂停汇报



# archive

1. 选择 change

2. 检查 artifact 完成情况

3. 检查 task 完成情况

4. 评估 delta spec 同步（合并策略）

5. 移动目录到 archive

6. 显示结果
