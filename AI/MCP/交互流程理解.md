# MCP 交互流程详解


Cline - 存在于智能体内部

# 单个 MCP 注册交互

1. 首先用 JSON 配置了一个 MCP Server

2. Cline 使用配置中的命令去执行这个程序（本地用 node / python 启动）

3. 执行了之后，这个程序会等待 Cline 的指令

4. Cline 询问当前的 MCP Server 可以提供哪些 Tool

5. 当前启动的 MCP Server 回复并列出所有 Tool 以及如何使用

6. Cline 记录回答以备后续使用

7. 到此为止，就完成了单个 MCP Server 的注册，发生在开启这个 MCP Server 的一瞬间


# 提问交互

1. Cline 拿到用户提问传给大模型，

2. 这里注意，和以往不一样的是，传给模型的除了用户的问题，还有前面所有已注册的 MCP Server 及 各自包含的 Tool，并告诉模型，这些 Tool 可能会帮助你解决用户的问题。

3. 模型经过思考，发现其中一个 MCP Server 的 Tool 可以回答用户的问题。

4. 模型就让 Cline 调用一下这个 Tool ，同时提供了 Tool 的入参。

5. Cline 收到模型的请求后，命令这个 MCP Server 用模型返回的参数调用 Tool

6. MCP Server 拿到执行后的结果传给 Cline

7. Cline 再把结果传给模型

8. 模型接到后，根据结果包装回答用户问题，并且把答案发给了 Cline

9. 最终 Cline 再把结果呈现给用户。



# 总结

Cline 相当于一层代理，用户只和 Cline 交互，Cline 去和内部配置的大模型去交互。

模型不调用工具，但是模型决定调用哪个工具，根据工具的描述来决定。
