# 注意力机制回顾（单字预测）

通过 Q / K 查询到 Value 之后，把所有查询到的这些 Value 加权 得到一个新的 Token（O）这就是 当前 QKV 的 O，O 再经过 FFN 进一步处理，得到这一层的输出。

再进入下一层的 Transformer，这样一层一层传递最后输出预测完成的下一个字。

# 那如果再预测下一个字呢

用笨办法，岂不是把之前预测完的所有字还要全部送进去，再走一遍上述流程（计算 QKV - 做 Attention - 得到 O - 跑 FFN）

不是的，这里引申出 “掩码自注意力”



# 掩码自注意力机制

每个 Token 只能看到自己和前面的 Token，绝对看不到后面的 Token。

所以当后面的 Token 生成之后，前面已经生成的 Token是不会变的。所以不变的部分就是 cache


# 具体做法

首先，以前计算过的 K / V 会缓存留在对应的 Transformer 层。

这些保存下来的 K / V 就是 KV Cache

比如下一个词有 20 层 Transformer，在经过每一层的时候都会直接用自己的 Q 去查询这一层的 K，加权后得到 自己的 O，用 O 跑一次 FFN， 直到第 20 层。


# 结论：用空间（内存）换时间（生成速度）

每生成一个新 Token 时，只生成自己的 Q / K / V，再用 Q 去查询当前层已缓存的 K / V，得到 O。

所以，在模型的 Decode （一个个Token正式往外生成）阶段，真正需要完整穿过几十层 Transformer 的只有最新的一个 Token，历史生成过的 Token 不再穿过。只是以 KV Cache 的形式留在了那里，等待新 Token 的查询。



# 疑问


# Q 去哪了？

为什么只保存 K / V

因为 每个 Token 的 Q 只会用一次，既在自己做 Attention 查询 KV Cache 的时候用一次，因为不会再生成新的 O，所以没用了。

所以叫 KV Cache，而不是 QKV Cache。


# 为什么不缓存 O ？

V 代表可以给别人提供什么信息

O 代表从别人那里拿回并汇总后的信息

所以，新 Token 只需要用自己的 Q 去查询历史 K 得到 V，那么历史的 O 对于下一个 Token 是没有意义的。
